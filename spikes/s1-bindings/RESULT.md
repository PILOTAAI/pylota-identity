# S1 Bindings smoke: result (in progress)

Run against Pylota's account on 2026-10-27 with the Worker `pi-spike-1` (workers.dev), built by
`worker-build` 0.8.7 from `spikes/s1-bindings`, whose only dependency is `crates/platform`. The entry points
come from `platform::export_worker!` and `platform::cf::glue`, which S1 wrote; the spike's own logic is in
`platform::cf::spike_s1` (feature `spike-s1`, deleted at M4).

## Done

| Check | Result |
|---|---|

| DO SQLite with `transactionSync` through the `platform::cf::externs` binding | **Pass.** A callback that inserts and then fails leaves 0 rows, and the error comes back to Rust; a callback that succeeds leaves its row |
| DO alarms | **Pass.** An alarm set 2 s ahead fired and ran the class's `alarm` |
| Queues: produce with `delay_seconds` | **Pass.** A message sent with a 3 s delay was first delivered 5.1 s later |
| Queues: `retry` with `delaySeconds` | **Pass**, with a timing note. Attempt 2 came 2.5 s after attempt 1 (delay 2 s); attempt 3 came 61 s after attempt 2 for the same 2 s delay. The design must not rely on a retry arriving at its delay; it is a lower bound |
| Queues: `Message::timestamp()` across retries | **Pass.** The same value (`1793130068478`) on attempts 1, 2 and 3, and `attempts` counts 1, 2, 3 |

## Finding for M4

`worker::Queue::send` with a `serde_json::Value` body delivers `{}`: `serde_wasm_bindgen` turns a JSON object
into a JS `Map`, which the queue's JSON content type drops. A body produced with `JSON.parse` and sent with
`send_raw` and `QueueContentType::Json` arrives intact. The platform's `QueueProducer` must send that way, and
its test must assert that a nested object survives the round trip.
